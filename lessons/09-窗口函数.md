# 09 · 窗口函数

> 本课目标：掌握 OVER/PARTITION BY/ORDER BY/帧（frame），熟练解决每组 Top N、累计、环比、排名等"聚合做不到"的问题。这是 SQL 查询能力的封顶一课，也是中高级后端面试的分水岭。

---

## 1. 为什么需要窗口函数

聚合函数（05 课）把 N 行**压成 1 行**，明细丢了：

```sql
SELECT user_id, SUM(total_cents) FROM orders GROUP BY user_id;   -- 每人一行，订单没了
```

窗口函数对每行计算一个"跨行结果"，**行数不变**——既看到明细，又看到统计：

```sql
SELECT
    id, user_id, total_cents,
    SUM(total_cents) OVER (PARTITION BY user_id)  AS user_total   -- 每行带着"该用户总额"
FROM orders
ORDER BY user_id, id;
```

一句话：**GROUP BY 是"压扁"，窗口是"广播"**。

## 2. OVER 子句解剖

```
函数(...) OVER (
    PARTITION BY <分组的列>     -- 按什么分桶（可省略=全表一桶）
    ORDER BY <排序的列>         -- 桶内按什么排（排名/累计类必需）
    ROWS/RANGE BETWEEN ...      -- 帧：桶内再切窗口范围（默认：排序后从起点到当前行）
)
```

```sql
-- 组内排名：每个分类内按价格排名
SELECT
    name, category_id, price_cents,
    ROW_NUMBER() OVER (PARTITION BY category_id ORDER BY price_cents DESC) AS rn,
    RANK()       OVER (PARTITION BY category_id ORDER BY price_cents DESC) AS rnk,
    DENSE_RANK() OVER (PARTITION BY category_id ORDER BY price_cents DESC) AS drank
FROM products
ORDER BY category_id, rn;
```

三个排名函数的区别（面试必考）：

| 价格（降序） | ROW_NUMBER | RANK | DENSE_RANK |
|---|---|---|---|
| 459900 | 1 | 1 | 1 |
| 329900 | 2 | 2 | 2 |
| 329900 | 3 | **2**（并列，跳号）| **2**（并列，不跳）|
| 299900 | 4 | **4**（跳过 3）| **3**（紧接）|

- `ROW_NUMBER`：无并列，1,2,3,4（并列时谁先随机，需加次级排序键保证稳定）；
- `RANK`：允许并列，并列后跳号（1,2,2,4）；
- `DENSE_RANK`：允许并列，不跳号（1,2,2,3）。

## 3. 经典题型一：每组 Top N

07 课预告的答案。**每个分类最贵的 2 个商品**，窗口函数是跨方言标准解：

```sql
WITH ranked AS (
    SELECT
        name, category_id, price_cents,
        ROW_NUMBER() OVER (PARTITION BY category_id ORDER BY price_cents DESC, id) AS rn
    FROM products
)
SELECT category_id, name, price_cents
FROM ranked
WHERE rn <= 2
ORDER BY category_id, rn;
```

三步套路：**窗口打行号 → 外层按行号过滤**。注意次级排序键 `id`——并列时保证结果确定（可复现的 API 响应）。

变体：

- Top 1（每组最 X 的一条）：`WHERE rn = 1`；
- 每组最后一条：`ORDER BY created_at DESC, id`；
- "去重保留最新"：按业务键 PARTITION，时间 DESC 打号取 1——数据清洗神器。

## 4. 经典题型二：累计与移动统计

```sql
-- 按月份累计销售额（年初至今）
SELECT
    substr(created_at,1,7) AS month,
    SUM(total_cents) AS monthly,
    SUM(SUM(total_cents)) OVER (ORDER BY substr(created_at,1,7)) AS cumulative
FROM orders
WHERE status <> 'cancelled'
GROUP BY substr(created_at,1,7)
ORDER BY month;
```

`SUM(SUM(x)) OVER (...)`：先 GROUP BY 聚合，窗口再对聚合结果累计——窗口函数在 GROUP BY **之后**执行（顺序：FROM→WHERE→GROUP BY→HAVING→**窗口**→SELECT→ORDER BY→LIMIT）。

### 环比（上月对比）

```sql
WITH monthly AS (
    SELECT substr(created_at,1,7) AS month, SUM(total_cents) AS revenue
    FROM orders WHERE status <> 'cancelled'
    GROUP BY substr(created_at,1,7)
)
SELECT month, revenue,
       LAG(revenue, 1) OVER (ORDER BY month)                       AS prev_month,
       revenue - LAG(revenue, 1) OVER (ORDER BY month)             AS diff,
       ROUND(100.0 * (revenue - LAG(revenue,1) OVER (ORDER BY month))
             / LAG(revenue, 1) OVER (ORDER BY month), 1)           AS pct
FROM monthly;
```

位移函数家族：`LAG(col, n)`（取前面第 n 行）、`LEAD(col, n)`（后面第 n 行）、`FIRST_VALUE` / `LAST_VALUE`（帧内首/末）、`NTH_VALUE`。

⚠️ `LAST_VALUE` 的经典坑：默认帧是"起点到当前行"，于是 LAST_VALUE 永远等于当前行！要么 `ORDER BY ... ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING`，要么直接用 `FIRST_VALUE` + 逆排序。

## 5. 帧（Frame）：桶内再切片

```
ROWS  BETWEEN <起点> AND <终点>
  UNBOUNDED PRECEDING   桶内第一行
  N PRECEDING           前面第 N 行
  CURRENT ROW           当前行
  N FOLLOWING           后面第 N 行
  UNBOUNDED FOLLOWING   桶内最后一行
```

```sql
-- 近 3 笔订单的移动平均（含当前行）——监控平滑、股票均线同款
SELECT
    id, created_at, total_cents,
    ROUND(AVG(total_cents) OVER (ORDER BY created_at, id
          ROWS BETWEEN 2 PRECEDING AND CURRENT ROW), 0) AS ma3
FROM orders
WHERE status <> 'cancelled';
```

细看帧子句：`2 PRECEDING AND CURRENT ROW` = 当前行 + 前两行，共 3 行参与平均。

```sql
-- 移动求和：每行 = 前1行+当前行+后1行的合计
SUM(total_cents) OVER (ORDER BY id ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING)
```

ROWS vs RANGE：`ROWS` 按物理行数；`RANGE` 按值范围（"同值算同帧"）。默认帧是 `RANGE UNBOUNDED PRECEDING TO CURRENT ROW`——**有 ORDER BY 时并列值会互相"看到"**，算累计去重场景时注意。

## 6. 常用窗口函数清单

| 类别 | 函数 |
|------|------|
| 聚合窗口化 | `SUM` `AVG` `COUNT` `MIN` `MAX` |
| 排名 | `ROW_NUMBER` `RANK` `DENSE_RANK` `NTILE(n)`（分桶）|
| 位移 | `LAG` `LEAD` `FIRST_VALUE` `LAST_VALUE` `NTH_VALUE` |
| 分布 | `PERCENT_RANK` `CUME_DIST`（百分位）|

```sql
-- NTILE: 把商品按价格分成 4 档（四分位数）
SELECT name, price_cents,
       NTILE(4) OVER (ORDER BY price_cents) AS quartile
FROM products;
```

## 7. 综合实战：用户订单明细报表

一行 SQL 同时给出：明细、该用户总额、该用户单内排名、全场排名、占总盘比例：

```sql
SELECT
    o.id,
    u.username,
    o.total_cents,
    SUM(o.total_cents) OVER (PARTITION BY o.user_id)                     AS user_total,
    ROW_NUMBER()     OVER (PARTITION BY o.user_id
                           ORDER BY o.total_cents DESC, o.id)            AS rank_in_user,
    RANK()           OVER (ORDER BY o.total_cents DESC)                  AS rank_global,
    ROUND(100.0 * o.total_cents /
          SUM(o.total_cents) OVER (), 1)                                 AS pct_of_all
FROM orders o
JOIN users u ON u.id = o.user_id
WHERE o.status <> 'cancelled'
ORDER BY rank_global
LIMIT 10;
```

`OVER ()` 空窗口 = 全表一桶。多个窗口写起来啰嗦？PG/SQLite 支持**命名窗口**复用：

```sql
SELECT
    SUM(total_cents) OVER w        AS user_total,
    ROW_NUMBER()     OVER w        AS rn,
    AVG(total_cents) OVER w        AS user_avg
FROM orders
WINDOW w AS (PARTITION BY user_id ORDER BY total_cents DESC);
```

## 8. 性能要点（13 课前传）

窗口函数需要**桶内排序**，成本 ≈ 排序 O(n log n)：

1. PARTITION BY 的列有索引 → 有机会走索引免排序；
2. 无法用 WHERE 过滤窗口结果（它在 SELECT 阶段才算）→ 过滤必须包一层（CTE/派生表），别试图在 WHERE 里写 `ROW_NUMBER()`（报错）；
3. 大表 + 复杂帧 = 内存排序 spill 到磁盘，EXPLAIN 里看到 `SORT` + `temp` 要警惕。

## 9. 常见坑

| 坑 | 修正 |
|---|---|
| WHERE 里用窗口函数结果 | 包 CTE/派生表后再过滤 |
| ROW_NUMBER 并列不稳定 | 排序键补一个唯一列（id） |
| LAST_VALUE 恒等于当前行 | 显式指定帧到 `UNBOUNDED FOLLOWING` |
| 以为窗口会减少行数 | 窗口永不改变行数（要减少行：+ 外层过滤/去重） |
| 窗口函数出现在 GROUP BY 前 | 顺序：先 GROUP BY 后窗口；对聚合结果开窗要嵌套 `SUM(SUM(x)) OVER` |
| 默认 RANGE 帧并列值串档 | 需要严格物理行时写 `ROWS BETWEEN` |

## 10. Rust 视角

窗口查询列多、类型杂，**用 `query!` 宏让编译器对齐 struct**最省心：

```rust
#[derive(sqlx::FromRow, Serialize)]
struct ProductRank {
    name: String,
    category_id: i64,
    price_cents: i64,
    rn: i64,            // ROW_NUMBER → i64
    rnk: i64,           // RANK → i64
    pct: Option<f64>,   // 涉除法/浮点 → Option 保险
}

let rows = sqlx::query_as::<_, ProductRank>(
    "WITH ranked AS (
        SELECT name, category_id, price_cents,
               ROW_NUMBER() OVER (PARTITION BY category_id ORDER BY price_cents DESC, id) rn,
               RANK()     OVER (PARTITION BY category_id ORDER BY price_cents DESC) rnk
        FROM products)
     SELECT * FROM ranked WHERE rn <= 3"
).fetch_all(&pool).await?;
```

"每组 Top N"在后端极常见（每个分类展示前 3、每个用户最新一条地址…），窗口函数 + CTE 组合请练到肌肉记忆。

## 练习

1. 给 products 打全店价格排名三件套（ROW_NUMBER/RANK/DENSE_RANK，降序），观察并列时三列的差异（造并列：`UPDATE products SET price_cents=89900 WHERE id=9`，做完重置）。
2. 每个用户的**最新一笔**订单（窗口 + rn=1），输出 username、order_id、created_at。
3. 全店按月销售额的**累计值**与**3 个月移动平均**（月份、当月、累计、MA3）。
4. 每个分类价格排名前 2 的商品中，再选出**全店库存总量 Top 3 的分类**各自的那两件商品。（多层 CTE 嵌套）
5. 找出每个用户金额**高于自己平均值**的订单（相关聚合的窗口写法：明细行 + `AVG(...) OVER (PARTITION BY user_id)` 比较）。

<details><summary>答案</summary>

```sql
-- 1.
SELECT name, price_cents,
       ROW_NUMBER() OVER (ORDER BY price_cents DESC, id) rn,
       RANK()       OVER (ORDER BY price_cents DESC) rnk,
       DENSE_RANK() OVER (ORDER BY price_cents DESC) drank
FROM products;

-- 2.
WITH ranked AS (
    SELECT o.id, o.created_at, u.username,
           ROW_NUMBER() OVER (PARTITION BY o.user_id ORDER BY o.created_at DESC, o.id DESC) rn
    FROM orders o JOIN users u ON u.id = o.user_id
)
SELECT username, id AS order_id, created_at
FROM ranked WHERE rn = 1 ORDER BY order_id;

-- 3.
WITH monthly AS (
    SELECT substr(created_at,1,7) m, SUM(total_cents) rev
    FROM orders WHERE status <> 'cancelled'
    GROUP BY substr(created_at,1,7)
)
SELECT m,
       rev,
       SUM(rev) OVER (ORDER BY m) AS cumulative,
       ROUND(AVG(rev) OVER (ORDER BY m ROWS BETWEEN 2 PRECEDING AND CURRENT ROW),0) AS ma3
FROM monthly ORDER BY m;

-- 4.
WITH top2 AS (
    SELECT p.id, p.name, p.category_id, p.price_cents, p.stock,
           ROW_NUMBER() OVER (PARTITION BY p.category_id ORDER BY p.price_cents DESC, p.id) rn
    FROM products p
),
cat AS (
    SELECT category_id FROM products GROUP BY category_id
    ORDER BY SUM(stock) DESC LIMIT 3
)
SELECT t.category_id, t.name, t.price_cents
FROM top2 t JOIN cat c ON c.category_id = t.category_id
WHERE t.rn <= 2
ORDER BY t.category_id, t.rn;

-- 5.
WITH stats AS (
    SELECT o.*, AVG(o.total_cents) OVER (PARTITION BY o.user_id) AS user_avg
    FROM orders o
)
SELECT id, user_id, total_cents, ROUND(user_avg,0) AS user_avg
FROM stats
WHERE total_cents > user_avg
ORDER BY user_id, total_cents DESC;
```
